# AutoVoice OS

A multi-module Android Automotive OS / Android Auto voice-assistant portfolio
project: **`:voice-sdk`** (a framework-agnostic Voice AI engine, shippable as
a standalone `.aar`) consumed by **`:app`** (a Clean Architecture + MVVM +
Jetpack Compose head-unit dashboard, with a second Car App Library surface
for Android Auto).

## Why this structure

Every folder boundary in this project maps to an actual architectural rule,
not just a naming convention — see the KDoc at the top of each file for the
full reasoning. The short version:

```
:voice-sdk                                  :app
──────────                                  ────
model/    → wire-level DTOs (Moshi)         domain/    → pure Kotlin, zero Android/SDK deps
network/  → Retrofit + mock NLU             data/      → the ONLY layer allowed to import :voice-sdk
engine/   → public VoiceEngine interface    di/        → Hilt wiring, lazy SDK init
audio/    → AudioFocus (AUDIOFOCUS_*)       presentation/ → Compose UI, StateFlow, UDF
                                             car/       → Car App Library (Android Auto surface)
```

**The one rule that makes this "Clean Architecture" and not just folders:**
only `data/repository/VoiceRepositoryImpl.kt` is allowed to import
`com.pawan.voicesdk.engine.*`. Everything else — ViewModel, UseCase, Compose
UI — depends on `domain/repository/VoiceRepository`, an interface, and knows
nothing about Retrofit, coroutine dispatchers, or the SDK's own failure
taxonomy. That boundary is what lets `DashboardViewModelTest.kt` unit-test
real business logic with a five-line fake and zero mocking framework.

## How to drop this into your existing Android Studio project

Your screenshot shows the project already scaffolded at
`~/AndroidStudioProjects/Autovoice` with `:app` and `:voice-sdk` modules
present but empty (autogenerated files only). To integrate:

1. Copy `gradle/libs.versions.toml` over your existing one.
2. Copy the root `settings.gradle.kts` and `build.gradle.kts`.
3. Copy `voice-sdk/build.gradle.kts`, `voice-sdk/consumer-rules.pro`, and
   everything under `voice-sdk/src/` into your `voice-sdk` module,
   **replacing** the autogenerated package if it isn't already
   `com.pawan.voicesdk` (Android Studio → right-click package → Refactor →
   Rename, don't hand-edit paths).
4. Do the same for `app/` → `com.pawan.autovoice`.
5. **File → Sync Project with Gradle Files.**
6. Run the `:app` `debug` build variant on a phone/tablet emulator first
   (fastest inner loop) before moving to the Android Automotive OS emulator
   (Tools → Device Manager → Create Device → category **Automotive**).

## What's implemented right now

- Full voice pipeline: utterance → `VoiceEngine` (mocked cloud NLU, with
  simulated latency AND simulated failures) → `VoiceCommand` → ViewModel →
  Compose UI, exercised end-to-end by tapping the orb.
- MVVM + UDF: one `StateFlow<DashboardUiState>`, one `onIntent()` entry point.
- Exhaustive, compiler-enforced `sealed` handling of every voice
  outcome/failure — nothing silently falls through a `when`.
- `AudioFocusManager` implementing the ducking-vs-exclusive distinction from
  the JD's Audio Focus question (not yet wired into the ViewModel — see
  roadmap).
- A second, genuinely distinct **Car App Library** surface (`car/`) alongside
  the Compose surface, demonstrating the "OEM-rendered template" model that
  Android Auto actually uses.
- Automotive-specific design constraints taken directly from Google's Design
  for Driving spec and cited in code comments where applied: 76dp minimum
  touch targets, 4.5:1 contrast, 32sp/24sp type scale, negative-polarity
  (dark) default theme, no irrelevant animation.
- Unit tests for both the SDK (`VoiceEngineImplTest`, fake `VoiceApiService`,
  `StandardTestDispatcher`) and the ViewModel (`DashboardViewModelTest`,
  fake `VoiceRepository`, `UnconfinedTestDispatcher` + Turbine).
- ProGuard/R8 `consumer-rules.pro` shipped inside the SDK so a minified host
  app doesn't silently break Moshi reflection.

## Roadmap — what to build next, in priority order for interview impact

1. **Real STT/TTS**: swap the orb's hardcoded demo utterance for Android's
   `SpeechRecognizer` (listen) and `TextToSpeech` (speak the `Speaking`
   state's text). Wire `VoiceAudioFocusManager.requestDuckingFocus()` around
   the listening phase and `requestExclusiveFocus()` around TTS playback —
   the class already exists in `:voice-sdk/audio`, it just isn't called yet.
2. **MediaSession integration**: back `MediaUiState` with a real
   `MediaSessionCompat` so `VoiceCommand.MediaControl` can control an actual
   `MediaPlayer`/ExoPlayer instance and other apps can see AutoVoice as a
   media-session-aware client.
3. **Wake-word background service**: a `foregroundServiceType="microphone"`
   `Service` that stays alive across `Application` process death guidance,
   demonstrating the "persistent mic connection without the OS killing your
   service" question directly.
4. **Room persistence**: conversation history + climate/media state survive
   process death — add `data/local/` with a `VoiceInteractionDao`.
5. **CarPropertyManager integration**: read real vehicle speed via
   `Car.createCar(context)` + `CarPropertyManager`, and gate voice-command
   auto-execution vs. confirmation-required behind actual driving state
   instead of always-on.
6. **CI**: GitHub Actions running `./gradlew testDebugUnitTest lint`, plus
   `detekt`/`ktlint` for the "Code Reviews" quality bar.
